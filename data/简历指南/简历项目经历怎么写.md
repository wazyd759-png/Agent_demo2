# 简历：项目经历怎么写

## 为什么项目经历最重要

对校招生来说，项目经历是简历的核心。HR 和技术面试官主要通过项目判断：

- 你的技术能力
- 你的工程思维
- 你的表达能力
- 你和岗位的匹配度

## 项目选择

### 选什么项目

优先选：

1. 有实际用户/数据的项目
2. 技术复杂度高的项目
3. 和岗位相关的项目
4. 你深度参与的项目

避免：

- 跟着教程敲的 Demo
- 只有 CRUD 的管理系统
- 团队项目但你说不清自己做了什么

### 几个项目合适

- 校招：2-3 个
- 社招：2 个深度项目 + 1 个其他

## 项目描述的黄金结构

### 1. 一句话背景

XX 是一个面向 XX 用户的 XX 系统，日活 XX，日均请求 XX。

要点：用户是谁、解决什么问题、规模多大。

### 2. 技术栈

技术栈：Python、FastAPI、PostgreSQL、Redis、Docker。

要点：列出核心技术，不要堆砌。

### 3. 你的工作（核心）

用 3-5 条描述，每条包含：

- 做了什么（动词开头）
- 怎么做的（技术方案）
- 结果如何（数字量化）

示例：

- 设计并实现基于向量检索的 RAG 问答系统，使用 Chroma + DashScope Embedding，检索命中率达到 100%，平均响应时间 1.5s
- 引入 CrossEncoder 重排，将 Top-3 来源的相关性从 0.85 提升到 0.99
- 使用 Docker 容器化部署，配合 Nginx 反向代理，支持公网访问

### 4. 项目成果

成果：上线后服务 500+ 用户，日均问答 2000+ 次，用户满意度 92%。

## 常见问题

### 问题 1：项目太简单，没什么可写

解决：

- 深挖技术细节：为什么选这个方案，有什么权衡
- 补充优化过程：从 v1 到 v2 改了什么
- 量化效果：性能提升了多少

### 问题 2：团队项目，我只做了一小部分

解决：

- 只写你做的部分，不要写整个项目
- 突出你的贡献和思考
- 如果做得太少，换一个项目

### 问题 3：没有实习，只有课程项目

解决：

- 把课程项目做深，补充工程化内容
- 自己找开源项目贡献
- 做一个个人项目并开源

### 问题 4：不知道怎么写结果

解决：

- 性能：QPS、延迟、吞吐量
- 规模：用户数、数据量、请求量
- 业务：转化率、留存率、增长
- 质量：准确率、召回率、覆盖率

## 项目描述的动词库

- 设计：设计、规划、定义、架构
- 开发：实现、开发、编码、搭建
- 优化：优化、重构、改进、提升
- 排查：排查、定位、修复、解决
- 协作：协调、推动、主导、配合

## 反面例子

### 反面 1：流水账

- 负责后端开发
- 使用 Spring Boot 写接口
- 和前端联调

问题：没有技术含量，看不出贡献。

### 反面 2：堆砌技术

- 使用 Spring Cloud、Kafka、Redis、MySQL、MongoDB、Elasticsearch、Docker、Kubernetes 构建微服务系统

问题：像技术清单，没有具体做了什么。

### 反面 3：没有结果

- 优化了系统性能

问题：优化了多少？从多少到多少？

## 正面例子

XX 推荐系统 | 2024.03 - 2024.06
技术栈：Python、PyTorch、Redis、MySQL

背景：为电商场景构建个性化推荐系统，服务 10 万日活用户。

我的工作：

- 设计双塔召回模型，使用用户行为序列训练，Recall@10 达到 0.65，相比 baseline 提升 20%
- 实现 Redis 缓存层，缓存热门商品向量，将推理延迟从 200ms 降至 50ms
- 搭建 AB 测试框架，支持 5 组策略并行对比，实验周期从 2 周缩短到 3 天

成果：上线后 CTR 提升 15%，DAU 增长 8%，GMV 提升 12%。

为什么好：

- 背景清晰
- 技术方案具体
- 结果量化
- 突出个人贡献

## 最后检查

- 每个项目能用 5 分钟讲清楚
- 每个技术点都能被追问 3 层
- 数字都是真实的，能解释来源
- 没有夸大或编造
- 和岗位要求相关
